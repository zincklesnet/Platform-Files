# v1.8.1 database and lease review

Corrected in 1.8.2:
- The prior `PRIMARY KEY (run_id)` could collide across sites; it is now `(site_id, run_id)`.
- Lease ownership alone was vulnerable to stale-worker release/heartbeat; a random fencing token is now required.
- Claims no longer permit same-owner takeover before expiry.
- Heartbeats fail after lease expiry.
- Tenant identity is injected into repositories instead of read dynamically during queries.
- Microsecond timestamps and InnoDB are explicit.
- The event table, previously only referenced, is created.

Remaining operational gates: validate `dbDelta` against supported MySQL/MariaDB versions, test deadlocks and clock skew, use DB server time consistently for lease deadlines, and run real multisite/network-activation migrations. JSON_EXTRACT requires a compatible database; provide a generated status column or normalized read model for older hosts.
